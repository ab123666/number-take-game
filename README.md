# number-take-game

「取数字博弈」：**双方轮流从 1~n 里挑一个没用过的数累加，先让总和达到或超过目标值的一方获胜**。对手是跑在 Web Worker 里的完全求解器 —— 位掩码 + 记忆化 DFS，理论上不可战胜。

[在线试玩](https://ab123666.github.io/number-take-game/)

## 特性

- **规则**：数字 `1 ~ n` 各只能用一次；总和达到 `target` 立即结束；没有平局。
- **参数范围**：目标 `1 ~ 351`（`MAX_TARGET = 1 + 2 + … + 26`），可选范围上限 26；下限由 `getMinDigit()` 推出 —— 取最小的 n 使 `1 + … + n ≥ target`，保证这局凑得满。
- **求解器**：`dfs(剩余, 已用位掩码)`，一命中必胜着法立即回溯；局面压缩成 `1 << n` 的位向量。
- **记忆化**：`Int8Array(1 << n)` 直接寻址 —— `0` 未计算、`>0` 必胜着法、`<0` 必败（绝对值是备选数），省掉 Map 的哈希开销。
- **不卡 UI**：AI 源码以字符串形式塞进 Blob URL 起 Worker，主线程只在「思考中」弹窗里转圈，搜索再深也不掉帧。
- **胜负预告**：电脑走完会回传 `computerWinning`，状态点变绿即表示它已经算到自己必胜。
- **必败时的走法**：全部分支都输时 `memo` 存最小备选数，所以电脑会走最靠前的可用数字 —— 不乱走，但也不做「最长抵抗」。
- **先手可选**：我先手 / 电脑先手。
- **零依赖**：单文件 HTML，无外部资源，`file://` 直接打开即可运行。

## 快速开始

```bash
git clone https://github.com/ab123666/number-take-game.git
cd number-take-game
python -m http.server 8000
```

打开 <http://localhost:8000>，或直接双击 `index.html`。

## 使用

1. 填目标总和（1–351）。
2. 选可用范围 `1 ~ n`：下拉只会列出 ≥ 下限的值，并标注该范围的数字总和。
3. 选先手。
4. 点数字落子，每次落子后总和立即刷新，达到目标即判定胜负。

## 必胜条件

这是个 Nim 型累加取数游戏：因为「总和 = 已用数字之和」，所以局面完全由「已用数字的集合」决定，与先后手历史无关。于是：

- 状态是 **P 位（必败）** 当且仅当它的所有后继都是 N 位（必胜）；
- 谁把 P 位交到对手手里，谁就赢。

用同一套递归枚举实测：

| n | target | 先手结论 |
|---|---|---|
| 10 | 40（默认） | 必败 |
| 10 | 41 | 必胜 |
| 10 | 43 | 必胜 |
| 6 | 21 | 必败 |
| 26 | 351 | 必败 |

默认参数（n = 10 / target = 40）恰好是先手必败态：选「我先手」时电脑稳赢；想赢就选「电脑先手」，把它放进必败位，之后每一步都走对。

## 复杂度与限制

- 状态数 `2^n`：n = 10 时 1024 项（瞬时），n = 26 时 6710 万项，`Int8Array` 约占 64 MB，首次求解在中低端手机上可能几百毫秒到数秒。
- 时间 `O(2^n · n)`，`n ≤ 26` 是硬上限（`MAX_DIGIT`）。
- 目标越大、可选数字越少，剪枝越早，反而更快。
- 电脑在必败局面下只走最小数字，不做最优「拖延」。
